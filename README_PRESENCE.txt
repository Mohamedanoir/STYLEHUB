Presence tracking (employee module)
===================================

The employee login appears first after the Oracle schema connection. After
sign-in, the employee dashboard opens and that employee is marked PRESENT.
CRUD stays available so the employee-module owner can continue the work.
Click "Deconnexion / Login" to set ABSENT and return to the login for the next person.

For an existing schema, the updated app first checks for ETAT_PRESENCE and
adds the column and check constraint if missing. The Oracle account must own
EMPLOYES (or have ALTER TABLE permission). Existing employee rows are kept and
default to ABSENT. Alternatively, run sql/03_add_employee_presence.sql once
in SQL Developer as the table owner; the script is safe to run again.

Daily attendance:
1. In the app, click "Connexion employe" on the manager dashboard.
2. The employee signs in with their EMP ID (for example EMP001) and password.
3. Their row is marked PRESENT in Oracle; the attendance window does not expose
   employee CRUD controls.
4. Click "Deconnexion / Employe suivant". Their row becomes ABSENT and the
   login form returns for the next employee.

The employee table reads the persisted attendance value from Oracle. On a new
empty schema, sql/01_create_six_tables.sql includes the same column already.
Do not run setup scripts that drop data; the attendance migration itself does
not drop tables or delete employees.

CV import accepts PDF files with selectable text, plus TXT and CSV files. It
fills recognized name, first name, job title and salary fields. The employee
ID is generated by Oracle; enter the employee password manually. Scanned/image
PDFs need OCR and cannot be read by this importer. Review all imported fields
before adding the employee.
